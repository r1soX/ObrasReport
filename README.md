# Отчёт по обработке обращений

Настольное приложение (WPF, .NET Framework 4.8) для автоматического формирования
отчёта по обработке обращений на основе нескольких выгрузок Excel за разные даты.

## Что нового: умный мастер и живой предпросмотр

- **Умный анализатор** — после загрузки файлов программа сама определяет формат,
  рекомендует оптимальный шаблон отчёта и показывает подсказку с предупреждениями.
  Кнопка «Применить рекомендацию» переключает режим одним кликом.
- **Мастер отчёта** (кнопка «Мастер отчёта…») — пошаговые вопросы с картинками-подсказками:
  1. Что хотите получить? (отчёт по обращениям / сравнение таблиц / динамика)
  2. Какая категория? (или «все»)
  3. Что показать в отчёте? (графики, статистика, комментарии)
  4. Как оформить? (выбор темы: синяя / зелёная / графит / светлая)
- **Живой предпросмотр** — перед сохранением открывается окно с тремя вкладками:
  - **«Сводная таблица»** — DataGrid со стилями как в Excel;
  - **«Графики»** — PNG-изображения, можно включать/выключать отдельные графики;
  - **«Статистика»** — текстовый блок с итогами.
  Слева — панель настроек: тема оформления, состав листов, выбор графиков.
  Изменения применяются мгновенно. Кнопка «Сохранить в Excel…» записывает
  именно то, что видит пользователь.

## Что делает

1. Загружаете **2 и более** выгрузок одной категории (перетаскиванием в окно или кнопкой «Добавить файлы…»).
   Поддерживаются **`.xlsx`, `.xlsm`, `.xls`, `.xlsb`** (Excel 97–2003 и современные книги).
2. Приложение автоматически:
   - определяет формат выгрузки (**«По ремонтам»** или **«Не по ремонту (цветные)»**);
   - берёт дату из имени файла и сортирует выгрузки по возрастанию;
   - сопоставляет обращения по **№ обращения** между всеми датами.
3. Если дата не распозналась из имени файла — выбираете её **календарём** в колонке «Дата»
   (список автоматически пересортируется по возрастанию).
4. При желании заполняете поле **«Описание отчёта»** — текст попадёт в отчёт.
5. По кнопке **«Сформировать отчёт»** сохраняет оформленный **`.xlsx`**.
   Для режима **«Обращения»** — отдельный файл **на каждую категорию**
   («По ремонту», «Не по ремонту», «Видеонаблюдение») с листами
   «Сводная таблица», «Статистика» и **«Графики»** (свои графики/диаграммы категории).
   Для режима **«Динамика»** — предпросмотр, затем листы «Динамика», «Статистика», «Графики».

## Графики режима «Обращения»

Строятся **отдельно по категории** отчёта:

1. линия — число обращений по датам;
2. для ремонтов — столбцы критичности (чёрная/красная/жёлтая) по датам;
3. столбцы — динамика между выгрузками (закрытые / новые / изменили состояние);
4. круговая — обработано / закрыто / на контроле (для ремонтов — с выделением «внешних»);
5. для ремонтов — круговая критичность на последнюю дату;
6. горизонтальные столбцы — топ‑10 ответственных с обращениями на контроле;
7. горизонтальные столбцы — топ‑10 ответственных по закрытым обращениям;
8. два полных рейтинга всех ответственных: обращения на контроле и закрытые обращения.

## Режим «Динамика» (закрытые обращения/наряды)

Нужны выгрузки со счётчиками «Количество обращений / (ЗАКРЫТО) / Количество нарядов / (ЗАКРЫТО)».
После «Сформировать отчёт» показываются:

**Графики**
1. линия — решено **обращений** по периодам;
2. линия — решено **нарядов** по периодам;
3. столбцы — обращения vs наряды по каждому периоду;
4. горизонтальные столбцы — топ‑10 ответственных по закрытым обращениям за последний период (с дельтой).

**Диаграммы**
5. круговая — доля закрытых обращений по ответственным (топ‑8 + «Прочие»);
6. кольцевая — обращения vs наряды за последний период.

Те же PNG попадают на лист **«Графики»** в Excel. Период (квартал и т.п.) задаётся
набором загруженных файлов и датами в списке; категория/смысл — в поле «Описание отчёта».

## Логика итога

| Итог | Когда присваивается |
|------|---------------------|
| **Обработано** | Для реестра «По ремонтам»: состояние обращения изменилось между выгрузками, обращение остаётся в последней выгрузке. |
| **Закрыто** | Обращение отсутствует в последней выгрузке. |
| **На контроле исполнения** | Обращение присутствует в последней выгрузке. Для ремонтов его состояние не изменилось либо обращение поступило недавно. |

Для «По ремонтам» обращения в состояниях, движение которых обеспечивают **внешние стороны**
(согласования, закупы, оплата, сервисный центр, ИТ-отдел, вторая линия), в комментарии
помечаются нейтрально — «ожидает …», без формулировок вида «требует действий администратора».
Список таких состояний задан в `Core/ReportEngine.cs` → `ExternalStates`.

Также автоматически отражаются: изменение состояния (траектория `A → B → …`),
переназначение ответственного, новые обращения.

## Как запустить (готовая сборка)

**Один файл** — `ReportIA.exe`. Все зависимости вплавлены внутрь через **Costura.Fody**,
поэтому exe запускается сам по себе, без сопутствующих DLL. Требуется .NET Framework 4.8
(входит в состав Windows 10/11).

Готовый файл лежит рядом: `..\ReportIA.exe` (и в `bin\Release\net48\ReportIA.exe`).

## Как собрать из исходников

```
dotnet build -c Release
```

Единый exe появится в `bin\Release\net48\ReportIA.exe` (Fody вплавляет все DLL в exe при сборке).
Открывается также в Visual Studio 2022 (`ObrasReport.csproj`).

> Примечание: `dotnet publish` использовать не нужно — он дополнительно раскладывает DLL рядом.
> Для «одного файла» берите exe из `bin\Release\net48`.

## Структура проекта

```
Models/Models.cs            модели данных (Snapshot, ObrRecord, ReportModel, Trend* …)
Core/XlsxReader.cs          читатель .xlsx/.xlsm/.xls/.xlsb (ZIP+XML + ExcelDataReader)
Core/RegistryParser.cs      автоопределение формата, разбор выгрузки, дата из имени файла
Core/ReportEngine.cs        сопоставление по датам и классификация Обработано / На контроле
Core/ReportAnalyzer.cs      умный анализатор: рекомендации по шаблону и предупреждения
Core/ReportConstants.cs     централизованные константы (итоги, категории, подписи колонок)
Core/ExcelReportWriter.cs   запись оформленного отчёта (ClosedXML → .xlsx)
Core/ClosedTrend*.cs        разбор / расчёт / запись отчёта динамики
Core/TrendChartRenderer.cs  графики режима «Динамика» (ScottPlot → PNG)
Core/ReportChartRenderer.cs графики режима «Обращения» по категориям
Core/ChartSheetHelper.cs    общий лист «Графики» в Excel
WizardWindow.xaml(.cs)      пошаговый мастер выбора отчёта
LivePreviewWindow.xaml(.cs) живой предпросмотр: таблица, графики, статистика, темы
ChartPreviewWindow.xaml     предпросмотр перед сохранением (старый, для динамики)
MainWindow.xaml(.cs)        интерфейс: список файлов, drag&drop, анализатор, формирование
```

## Зависимости

- **ClosedXML** 0.102.3 — запись `.xlsx`.
- **ExcelDataReader** 3.7.x — чтение `.xls` / `.xlsb` и запасной путь для Open XML.
- **ScottPlot** 4.1.x — графики и диаграммы режима «Динамика» (PNG в UI и на листе «Графики»).
- **Costura.Fody** 5.7.0 + **Fody** 6.8.1 — вплавление всех DLL в единый exe.
- Для `.xlsx`/`.xlsm` — собственный ZIP+XML-парсер (устойчив к регистру `xl/SharedStrings.xml`
  в выгрузках 1С), с откатом на ExcelDataReader при ошибке.

## Примечания по форматам

**Файлы входа:** `.xlsx`, `.xlsm`, `.xls`, `.xlsb`.  
**Файл отчёта:** всегда `.xlsx` (совместим с Excel 2007+ и современными редакторами).

Приложение опирается на структуру выгрузок:
- **По ремонтам**: колонки Классификатор / КЕ / Филиал / Состояние / Состояние дней + флаги критичности Жёлтая/Красная/Чёрная; строка-группа = Ответственный.
- **Не по ремонту**: колонки Клиент / Состояние / Конфигурационная единица; строка-группа = Ответственный.

Сопоставление колонок — по подписям заголовков, поэтому небольшие сдвиги столбцов допустимы.
Если формат не распознан — в списке файлов будет отмечено «Не определён».
